# 自動排程系統說明

## 一、使用動機

**手動排程的問題：**
- 50+ 任務互相依賴時，人工計算每個任務的開始/結束日期極易出錯
- 一個任務延遲，所有後續任務都要手動調整
- 無法快速回答「專案最早何時完成？」「哪些任務不能延遲？」

**自動排程解決什麼：**
- 根據前置關聯 + 工期 + 行事曆，自動計算所有任務的最早/最晚日期
- 一鍵重排：任何變動後重新計算整條鏈
- 自動標示關鍵路徑（零浮時任務），讓管理者知道哪些任務絕不能延遲

## 二、專案範例

### 範例：軟體開發專案（正排）

```
專案開始：2026-03-01
排程方向：正排（Forward / ASAP）

任務               工期    前置關聯        約束          排程結果
─────────────────────────────────────────────────────────────────
A 需求分析          3天     (無)           ASAP         03/01 → 03/03 ★
B 系統設計          5天     A (FS)         ASAP         03/04 → 03/08 ★
C UI 設計           3天     A (FS)         ASAP         03/04 → 03/06
D 後端開發          8天     B (FS)         ASAP         03/09 → 03/16 ★
E 前端開發          6天     B (FS)+C (FS)  ASAP         03/09 → 03/14
F 整合測試          4天     D (FS)+E (FS)  ASAP         03/17 → 03/20 ★
G 部署上線          1天     F (FS)         SNET 03/21   03/21 → 03/21 ★

專案結束：2026-03-21
關鍵路徑：A → B → D → F → G（★ 標記）
```

**解讀：**
- C 和 E 有浮時（C 可延遲 2 天不影響專案），不在關鍵路徑上
- G 設了 SNET（開始不早於 03/21），即使 F 提前完成也等到 03/21 才部署
- D 延遲 1 天 → F、G 都延 1 天 → 專案延到 03/22

### 範例：含 Lag 的建築專案

```
A 灌漿              2天     (無)
B 養護等待           -      A (FS, lag=3天)    → A 完成後等 3 天才開始 B
C 拆模              1天     B (FS)
```

### 範例：逆排（Backward / ALAP）

```
專案截止：2026-06-30
排程方向：逆排（Backward）

→ 從截止日往回推，計算每個任務的最晚開始日
→ 所有任務盡量延後，但不超過截止日
```

## 三、使用條件

### 必要條件

| 條件 | 設定位置 | 說明 |
|------|----------|------|
| 專案排程方向 | 專案 → 甘特圖設定 → `scheduling_type` | `forward`（正排）或 `backward`（逆排），不可為 `manual` |
| 專案起始日 | 專案 → `schedule_start` | 正排必填，系統自動設為當前時間（若空） |
| 專案截止日 | 專案 → `schedule_end` | 逆排必填 |
| 任務排程模式 | 任務 → `schedule_mode` = `auto` | **只有 auto 的任務會被排程器計算**，manual 任務保持原位 |
| 任務工期 | 任務 → `plan_duration` | 以小時為單位（預設 24h = 1 工作天） |

### 建議條件

| 條件 | 說明 |
|------|------|
| 前置關聯 | 至少部分任務之間建立 FS/SS/FF/SF 連結，否則全部從專案起始日開始 |
| 行事曆 | 啟用 `use_calendar` 後，排程器依工作時段排除假日/非工時 |
| 約束 | 對有硬性日期要求的任務設定 SNET/FNLT/MSO 等約束 |

## 四、計算原理

### 4.1 雙向推算法（CPM — 關鍵路徑法）

```
┌─────────────────────────────────────────────────┐
│  第一步：正排（Forward Pass）→ 最早開始/完成    │
│                                                  │
│  從專案起始日出發，依前置關聯順序推算：          │
│  ES(B) = max( EF(所有B的前置任務) + lag )        │
│  EF(B) = ES(B) + 工期                           │
│                                                  │
├─────────────────────────────────────────────────┤
│  第二步：計算專案結束日                          │
│                                                  │
│  schedule_end = max( EF(所有任務) )              │
│                                                  │
├─────────────────────────────────────────────────┤
│  第三步：逆排（Backward Pass）→ 最晚開始/完成   │
│                                                  │
│  從專案結束日倒推：                              │
│  LF(A) = min( LS(所有A的後續任務) - lag )        │
│  LS(A) = LF(A) - 工期                           │
│                                                  │
├─────────────────────────────────────────────────┤
│  第四步：關鍵路徑                                │
│                                                  │
│  浮時 = LS - ES（或 LF - EF）                    │
│  浮時 = 0 的任務 → 關鍵路徑（紅色標示）         │
│                                                  │
├─────────────────────────────────────────────────┤
│  第五步：ALAP 約束後處理                         │
│                                                  │
│  constrain_type = 'alap' 的任務使用最晚日期     │
│  並重新推算其後續任務                            │
└─────────────────────────────────────────────────┘
```

### 4.2 四種前置關聯類型

| 類型 | 意義 | 正排公式 |
|------|------|----------|
| **FS**（完成到開始） | B 在 A 完成後才能開始 | `ES(B) = EF(A) + lag` |
| **SS**（開始到開始） | B 在 A 開始後才能開始 | `ES(B) = ES(A) + lag` |
| **FF**（完成到完成） | B 在 A 完成後才能完成 | `EF(B) = EF(A) + lag` |
| **SF**（開始到完成） | B 在 A 開始後才能完成 | `EF(B) = ES(A) + lag` |

- **Lag 正值**：延遲（A 完成後等 3 天才開始 B）
- **Lag 負值**：前置時間（A 完成前 2 天就可以開始 B）
- **Lag 單位**：`day`（天）、`hour`（小時）、`minute`（分鐘）

### 4.3 八種約束類型

| 約束 | 中文 | 行為 |
|------|------|------|
| `asap` | 盡早開始 | 無約束，依前置關聯排（預設） |
| `alap` | 盡晚開始 | 使用逆排日期，盡量延後 |
| `snet` | 開始不早於 | `start >= constrain_date`，若違反則推遲到約束日 |
| `snlt` | 開始不晚於 | `start <= constrain_date`，若違反則提前到約束日 |
| `fnet` | 完成不早於 | `end >= constrain_date`，若違反則從約束日逆推 |
| `fnlt` | 完成不晚於 | `end <= constrain_date`，若違反則從約束日逆推 |
| `mso` | 必須開始於 | `start = constrain_date`，強制釘死 |
| `mfo` | 必須完成於 | `end = constrain_date`，強制釘死 |

**優先順序**：`MSO/MFO` > `SNET/SNLT/FNET/FNLT` > 前置關聯 > `ASAP/ALAP`

### 4.4 行事曆如何影響排程

啟用 `use_calendar` 後：

```
工期 = 24 小時（plan_duration）
工作時段 = 週一~五 09:00-18:00（8 小時/天，扣除午休）

實際排程：
  開始 = 2026-03-01 (週一) 09:00
  Day 1 = 8h → 18:00
  Day 2 = 8h → 03/02 18:00
  Day 3 = 8h → 03/03 18:00  (24h 完成)
  結束 = 2026-03-03 18:00

如果不啟用行事曆：
  開始 = 2026-03-01 09:00
  結束 = 2026-03-02 09:00  (直接 + 24 小時)
```

### 4.5 父子任務處理

- **父任務**（有子任務的任務）：`summary_date_start` / `summary_date_end` 自動計算為子任務的最小開始 / 最大結束
- 排程器只計算葉任務，父任務的日期是匯總結果
- 前端拖曳父任務 → `moveRecordWithChildren()` 所有子任務等距移動

### 4.6 循環依賴偵測

```
A → B → C → A  (循環！)

偵測方式：BFS 遍歷後續鏈
  ├─ 建立時：@api.constrains 立即阻擋，拋出 ValidationError
  └─ 排程時：visited_stack 追蹤，設 p_loop = True，標示於違規面板
```

## 五、操作說明

### 5.1 初始設定

1. **開啟專案** → 甘特圖設定頁籤
2. **排程方向**：選擇「正排（Forward）」或「逆排（Backward）」
3. **專案起始日**：設定（或留空，排程時自動設為現在）
4. **啟用行事曆**：勾選（使用資源的工作時段）
5. **預設工期**：設定新任務的預設小時數（如 24 = 3 工作天）

### 5.2 建立任務與關聯

1. **建立任務**：在甘特圖上點擊空白處或使用工具列「+」
2. **設定工期**：在檢查器面板輸入 `plan_duration`（小時）
3. **設為自動排程**：`schedule_mode` = `auto`（關鍵！manual 的任務不會被計算）
4. **建立前置關聯**：
   - 拖曳任務右端圓點 → 拉虛線到目標任務
   - 自動建立 FS 連結，lag 從兩任務間距自動計算
5. **設定約束**（可選）：在檢查器選擇約束類型 + 約束日期

### 5.3 執行排程

| 操作 | 工具列按鈕 | 效果 |
|------|------------|------|
| **排程** | 排程按鈕 | 全專案 CPM 雙向推算，計算所有 auto 任務日期 + 關鍵路徑 |
| **重新排程** | 重新排程 | 只重排未完成的任務（保留已完成任務位置） |
| **追趕進度** | 追趕進度 | 將落後任務推到今天，重新排程剩餘工作 |

### 5.4 前端即時排程（拖曳互動）

| 操作 | 自動行為 |
|------|----------|
| 拖曳任務左右移動 | 所有 FS 後續任務自動推移 → 相關 lag 自動重算 |
| 縮放任務（改變結束日） | 同上 |
| 建立新的 FS 連線 | 自動計算初始 lag → 若後續任務違反約束則推移 |
| 在檢查器修改 lag | 後續任務移動到 `predecessorEnd + newLag` → 級聯推移 |
| 拖曳父任務 | 所有子任務等距移動 → 後續鏈級聯 |

### 5.5 批次操作

在甘特圖選取多個任務（Shift+點擊），工具列出現：
- **設為自動**：批次 `schedule_mode = 'auto'`
- **設為手動**：批次 `schedule_mode = 'manual'`
- **清除約束**：批次移除 `constrain_type` 和 `constrain_date`

### 5.6 違規檢視

排程完成後，違規面板顯示：
- **循環依賴**：`p_loop = True` 的任務
- **約束衝突**：實際日期違反約束的任務
- **資源過載**：同一資源同時段分配多個任務
- **超期任務**：結束日超過截止日的任務

點擊違規項目 → 自動定位到該任務。
